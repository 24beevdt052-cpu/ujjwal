# CONTRACTS.md — shared build contract for every contributor (human or agent)

Scope source of truth: `docs/spec/MASTER_SPEC_V3.md` (tables 1–9). This file fixes the *interfaces* so phases can
be built independently and still reconcile to the rupee. If you must change a contract, change it here in the same
edit and say why.

> This project is unrelated to the NHAI face-attendance app in `~/Desktop/NHAI_HACKATHON`; ignore that repo's
> CLAUDE.md for anything in this folder.

## 1. Ground rules
1. **Simulation label.** Every chart (`desk.reporting.style.save_fig` does it), report, workbook sheet and PDF
   carries `desk.SIM_LABEL` = "ACADEMIC SIMULATION — not actual trades". All counterparties/vessels end in "(SIM)".
2. **Provenance flags.** Every input series and parameter is `DIRECT` (observed from a named public source),
   `PROXY` (a real observable standing in for the thing we need, or a transformation of real data), or
   `ASSUMPTION` (a judgement, with justification). **Never label reconstructed or remembered numbers DIRECT.**
   Never invent a "real" headline, price or document. If a fetch fails, fall back to a clearly-flagged proxy.
3. **Units** (Table 8.3). Column suffixes per `desk/units.py`: `_usd_t`, `_inr_t`, `_inr_kg`, `_mt`, `_usd`,
   `_inr`, `_pa`, `_frac`; `usdinr` = INR per USD. Convert only through `desk.units`. LME "$/t" ≡ USD/MT.
4. **Base currency INR.** The desk is an Indian importer; P&L is reported in ₹ (USD shown as memo).
5. **Determinism.** Any randomness seeds from `desk.RNG_SEED` via `numpy.random.default_rng`. Re-running
   `run_all.py` must reproduce every output byte-for-byte except timestamps.
6. **No hard-coded magic numbers** in model code: parameters come from `config/params/*.yaml` via
   `desk.config.value(key, date)`. Model-structure constants (e.g. 10,000 MC paths, 95 %) may live in code as
   named constants.
7. **Stages talk through files only.** Each stage module exposes `main() -> None`, reads upstream files, writes its
   own outputs, and is registered in `run_all.py`. Network access only in `fetch_*` modules; every fetcher caches
   to `data/raw/` and honours `DESK_OFFLINE=1` (use cache, never network). Wrap network calls in retries
   (this machine has a flaky TLS path).
8. **Python:** `.venv/bin/python` (3.12; pinned `requirements.txt`). Tests: `.venv/bin/python -m pytest -q`.
   Code style: typed, small functions, docstrings that explain *why*; pandas vectorised where natural.
9. **Every quant model** ships a plain-English "What this does and doesn't tell you" paragraph (Table 8.5).

## 3. Calendar
- Panel calendar = LME trading days from the Westmetall LME official price tables, `HISTORY_START` (2018-01-02)
  → `PANEL_END` (2022-12-30). Headline window `WINDOW_START`–`WINDOW_END` (2022-03-01 → 2022-08-31); engine horizon
  runs to `HORIZON_END` (2022-09-30) so trades can settle. All of these, and `MAX_FILL_BDAYS`, live in `desk/__init__.py`.
- Series on other calendars (ECB FX, US Treasury bills, weekly freight) are aligned to the LME calendar by
  **point-in-time forward-fill** — a day only sees values already published on or before it — **with a `*_filled`
  boolean column** (max `MAX_FILL_BDAYS` = 5 business days; longer gaps raise). Weekly freight becomes available on
  its Thursday WCI assessment date (week_end − 1 day), so Monday–Wednesday carry the previous week's value.
  (Amended in the Phase 0 review: the first build mapped each day to its containing Friday week, i.e. up to 3 days of
  look-ahead, which contradicted this rule.)
- "Week" = week ending Friday (`W-FRI`); weekly value = last available panel day in that week.
- MCX holidays are not modelled (documented ASSUMPTION): MCX proxy prices are on the LME calendar.

## 4. Phase 0 data contracts

### 4.1 `data/processed/lme_daily.csv` (desk.data.fetch_lme) — DIRECT
`date, lme_cash_usd_t, lme_3m_usd_t, lme_cash_3m_spread_usd_t, lme_stock_mt`
- Source: westmetall.com "LME Aluminium Cash-Settlement / 3-month / stock" yearly tables (they republish LME
  official prices). Spread = cash − 3M (**positive = backwardation, negative = contango**).
- Cached raw HTML: `data/raw/westmetall_lme_al_<year>.html` for 2018–2022 (2023–2025 also cached for price evidence).
- Column renamed `lme_stock_t` → `lme_stock_mt` in the Phase 0 review: the contract itself broke the §1.3 suffix rule
  (`_mt` = quantity, `_t` only inside rates such as `_usd_t`).

### 4.2 `data/processed/fx_rates_daily.csv` (desk.data.fetch_fx)
`date, usdinr, usdinr_src, rbi_repo_pa, fed_funds_upper_pa, inr_rate_3m_pa, usd_rate_3m_pa, usd_rate_3m_filled,
rates_src, fwd_premium_3m_pa, usdinr_fwd_1m, usdinr_fwd_3m`
- `usdinr` = ECB EUR/INR ÷ ECB EUR/USD reference rates, a PROXY for the RBI/FBIL reference rate. It is expected to
  be close but the gap has **not been measured** (the ECB fixing is ~4–5 h after the 13:30 IST reference and the cross
  moved a median 12 paise a day in the window; PENDING: compare ≥ 10 window dates with FBIL reference rates).
  `usdinr_src` ∈ {ECB_CROSS, MANUAL_RBI}. `data/manual/rbi_reference_rate.csv` (`date,usdinr,source`; `source` must
  name RBI or FBIL on every row) overrides the cross on its dates.
- `rbi_repo_pa`, `fed_funds_upper_pa` are **DIRECT** step paths from `rates.yaml`, each step verified against the RBI
  MPC release / Federal Reserve table. `inr_rate_3m_pa`, `usd_rate_3m_pa`, `fwd_premium_3m_pa` and the forwards are
  **PROXY** (OECD IR3TIB spread over repo; US 13-week bill; covered interest parity via `desk.units.fx_forward`).
  (Amended in review: the first text called the policy-rate paths PROXY while the files, correctly, said DIRECT.)
- `usd_rate_3m_filled` = the Treasury print was carried over a US holiday. `rates_src` =
  `USD:<UST13W|FALLBACK_FEDFUNDS_SPREAD>|INR:<OECD_IR3TIB|FALLBACK_REPO_SPREAD>`. Under `DESK_OFFLINE=1` a missing
  or invalid rate cache raises; online, an unavailable year/month falls back to policy rate + term spread for those
  dates only, is labelled here, and `build_panel` downgrades the rate columns to ASSUMPTION in `series_provenance.csv`.

### 4.3 `data/processed/freight_weekly.csv` (desk.data.fetch_freight)
`week_end, freight_jea_nsa_usd_t, freight_usec_mun_usd_t, index_name, index_value, freight_src, note`
- Lanes: **JEA_NSA** = Jebel Ali → Nhava Sheva (20ft containers, sold to a SIM buyer near JNPT); **USEC_MUN** = US East
  Coast → Mundra (40ft, sold into Gujarat).
- USD per MT of scrap = USD per box ÷ BASE payload MT per box (`logistics.yaml`); grade payloads rescale it in §5.
  Shape (Drewry WCI) = PROXY; lane level calibration = ASSUMPTION — so both freight columns are flagged ASSUMPTION in
  `series_provenance.csv`, and `freight_src` gives the per-week shape/level tags (filter on it, not on the flag).
- **Look-ahead:** levels are hindsight-calibrated. Anchors carry `available_from` (latest publication date of every
  article they depend on) in `data/interim/freight/points_india_inbound_anchors.csv`, and each weekly `note` states
  when that week's level inputs became public (up to ~7 months after Mar-2022 weeks). WCI_DERIVED/INTERPOLATED shape
  weeks use the next week's publication. No point-in-time level exists for Mar–Apr 2022 in the cached sources, so
  later phases must treat freight as a reconstruction and test decisions for freight sensitivity.

### 4.4 `data/processed/headlines_weekly.csv` (desk.sentiment.fetch_news) — DIRECT (headline text)
`week_end, published_utc, source, title, link, query`
- Google News RSS search with `after:/before:` operators per week (Feb 25 → Sep 2, 2022), aluminium/LME/scrap/
  steel queries; de-duplicated; raw XML cached in `data/raw/news/`. Headlines are real public RSS items — store as
  returned, never paraphrase or invent. Sentiment scoring is P7 (`desk.sentiment.run`).
- Google returns a page's current (possibly re-edited) title with its original pubDate, so titles beginning
  "Update"/"Updated" are excluded and titles citing a later day-month are listed for review (audit in `data/interim/news/`).

### 4.5 `data/processed/market_daily.csv` (desk.data.build_panel) — THE panel every later phase reads
One row per LME trading day, 2018-01-02 → 2022-12-30:
```
date, in_window,
lme_cash_usd_t, lme_3m_usd_t, lme_cash_3m_spread_usd_t, lme_stock_mt,
usdinr, usdinr_filled, usdinr_src, rbi_repo_pa, fed_funds_upper_pa, inr_rate_3m_pa, usd_rate_3m_pa,
usd_rate_3m_filled, rates_src, fwd_premium_3m_pa, usdinr_fwd_1m, usdinr_fwd_3m,
mcx_al_spot_inr_kg, mcx_al_m1_inr_kg, mcx_al_m2_inr_kg, mcx_m1_expiry, mcx_m2_expiry, mcx_src,
freight_jea_nsa_usd_t, freight_usec_mun_usd_t, freight_filled, freight_src
```
- **MCX Aluminium (5 MT lot, ₹/kg).** If `data/manual/mcx_aluminium_*.csv` (bhavcopy extracts:
  `date,contract_expiry,close_inr_kg,source`, `source` naming an MCX bhavcopy file or mcxindia.com URL on every row)
  exist → those days are `mcx_src = MANUAL`; an MCX non-trading day strictly inside the manual coverage carries the
  previous close as `mcx_src = MANUAL_FFILL` (this label is the MCX fill flag; ≤ `MAX_FILL_BDAYS`); days outside the
  coverage use the proxy. The MCX columns are DIRECT only if no day is a proxy day. Otherwise PROXY
  (`mcx_src = PROXY_IMPORT_PARITY`):
  `mcx_al_spot_inr_kg = lme_cash_usd_t × usdinr / 1000 × (1 + bcd_primary_al_hs7601 × (1 + sws_rate_on_bcd)) + mcx_domestic_premium_inr_kg`
  and futures `m1/m2 = spot × (1 + inr_rate_3m_pa × days_to_expiry / 365)` with expiry = last calendar day of the
  month (previous business day if not a panel day). Rationale: MCX Aluminium trades at duty-paid import parity.
  The proxy is unbiased over the window but too high in the March-2022 spike and too low in May–July (market_proxy.yaml).
- `usd_rate_3m_filled` in the panel = Treasury carry OR the whole FX row carried (`usdinr_filled`).
- `freight_filled` = the freight value was assessed on an earlier day (point-in-time carry, §3).
- `data/processed/series_provenance.csv`: `column, flag, source, transformation, unit` — one row per panel column.
  Flags are recomputed from the sources actually used (MANUAL_RBI / MANUAL MCX / rate fallbacks); indicator and label
  columns carry the weakest flag of the series they qualify.

## 5. Shared desk economics (P1 implements; Excel must reproduce the same formulas)
Per MT of scrap, week `w` (values on the week's last panel day), grade `g` ∈ {zorba (= Zorba 95/5), taint_tabor,
tense}, lane `l` ∈ {JEA_NSA (20ft), USEC_MUN (40ft)}:
```
cfr_usd_t          = lme_3m_usd_t × grade_factor_g(w)        grade factor = CFR-India price as % of LME 3M, SAME for both lanes
payload_scale_l_g  = container_payload_mt_<box_l> / container_payload_mt_<box_l>_<g>        (box_l = 20ft | 40ft)
freight_l_g_usd_t  = freight_l_usd_t × payload_scale_l_g                                     (panel freight is at base payload)
fob_usd_t_l        = cfr_usd_t − freight_l_g_usd_t           memo: origin netback = the price basis of an FOB-term trade
insurance_usd_t    = insurance_rate × insured_value_uplift × cfr_usd_t
cif_usd_t          = cfr_usd_t + insurance_usd_t
av_customs_inr_t   = cif_usd_t × customs_usdinr_import(w)    DUTY BASE ONLY (landing_charges_frac = 0)
goods_inr_t        = cif_usd_t × usdinr                      what the importer pays: market spot (P1 may use usdinr_fwd_*
                                                              matched to the LC payment date instead, and must say which)
bcd_inr_t          = av_customs_inr_t × bcd_scrap_hs7602
sws_inr_t          = bcd_inr_t × sws_rate_on_bcd
igst_inr_t         = (av_customs_inr_t + bcd_inr_t + sws_inr_t) × igst_rate_hs7602           paid on the Bill of Entry
port_inr_t         = port_cf_charges_inr_t_<nsa|mun> × payload_scale_l_g
                     + [JEA_NSA only: non-safe origin] psic_cost_usd_per_box × usdinr / container_payload_mt_20ft_<g>
finance_inr_t      = (goods_inr_t + bcd_inr_t + sws_inr_t) × finance_days_l / 365 × wc_rate_inr_pa(w)
igst_finance_inr_t = igst_inr_t × igst_credit_lag_days / 365 × wc_rate_inr_pa(w)   IGST financed from BoE to GSTR-3B offset
landed_inr_t       = goods_inr_t + bcd_inr_t + sws_inr_t + port_inr_t + finance_inr_t + igst_finance_inr_t
                     [+ igst_inr_t only if igst_itc_available is false]
recovery_frac_g    = (1 − moisture_frac_g) × (1 − contamination_frac_g) × metal_yield_frac_g   aluminium ingot per MT scrap
anchor_inr_t       = mcx_al_<M1 for JEA_NSA | M2 for USEC_MUN>_inr_kg × 1000 + domestic_anchor_premium_inr_t
                     (secondary-ingot price; the MCX contract is matched to the lane's domestic sale date)
byproduct_inr_t    = (1 − moisture_frac_g) × heavies_frac_g × heavies_net_value_frac_of_lme_al × lme_3m_usd_t × usdinr
conversion_inr_t   = conversion_cost_inr_t × recovery_frac_g                  conversion cost is quoted per t of INGOT
net_arb_inr_t      = anchor_inr_t × recovery_frac_g + byproduct_inr_t − landed_inr_t − conversion_inr_t
window_open        = net_arb_inr_t > margin_threshold_inr_t
```
(This is Table 3.4's "anchor − landed > conversion + margin" expressed per MT of scrap so the Table 1.6 recovery
logic is explicit.) Parameter names above are the canonical YAML keys; P1 may add keys but not rename these.

**Required P1 sensitivities** (the base flag alone is not a result): window_open under `grade_factor_mix_lag1`,
`_lag3` and `_pit` in place of the lag-2 mix; each grade differential ± its evidence IQR (scrap_grades.yaml);
every value of `domestic_anchor_premium_sensitivity_inr_t` and the sticky variant
`anchor_sticky_inr_t = mean(mcx_al_spot_inr_kg × 1000 over the previous domestic_anchor_trailing_bdays LME days) +
domestic_anchor_premium_trailing_inr_t`; every `conversion_cost_sensitivity_inr_t_ingot`; recovery and heavies-value
ranges in the YAML notes; the anchor on the third-party MCX mirror M1 (data/interim, PROXY); and a statement that the
freight levels and the lag-2 grade mix are hindsight reconstructions (§4.3, scrap_grades.yaml).

**Change log (Phase 0 review, 2026-09-16) — why §5 changed:**
1. *CFR parity.* The first version applied one FOB factor to both lanes, so the Gulf lane booked its entire freight
   saving (~₹5–7k/t) as margin every week. Gulf sellers price on a CFR-India netback and the price evidence (DGCIS CIF
   unit values, BigMint CFR quotes) is on a CFR/CIF basis, so the grade factor is now CFR and FOB is a memo netback.
2. *Customs FX only for duty.* `av_inr_t = cif × customs_usdinr` valued the goods at the CBIC notified rate (~1.1% above
   market, frozen for a fortnight), overstating landed cost by ~₹1.5k/t on average. The notified rate now sets only the
   duty base; goods are paid at the market rate. The key was also misnamed (`customs_usdinr` → `customs_usdinr_import`).
3. *Conversion unit.* The conversion evidence is per tonne of ingot, so it is multiplied by recovery.
4. *Zorba heavies.* The Zorba price evidence is for Zorba 95/5, whose ~5% heavy non-ferrous fraction is sold; the
   by-product credit makes recovery and price refer to the same material.
5. *IGST financing* is stated explicitly (financed for `igst_credit_lag_days`, excluded from landed cost with ITC).
6. *PSIC* (Gulf origin) and *grade-specific payloads* enter port/freight costs; the anchor uses the MCX contract that
   matches the sale date; `wc_rate_inr_pa` is now a dated path.
